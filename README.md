# KoaZa Foreseer — کوازا آینده‌نگر

برنامهٔ دسکتاپ ویندوز برای تحلیل آماری فوتبال و برآورد احتمال بازارهای مسابقه. رابط فارسی و راست‌به‌چپ است و داده‌ها به‌صورت محلی نگهداری می‌شوند.

> وضعیت فعلی: سورس برنامه در حال توسعه است. ساخت فایل اجرایی ویندوز از طریق GitHub Actions پیکربندی شده است؛ تا زمانی که اجرای موفق workflow تأیید نشده باشد، این README تضمین نمی‌کند که فایل اجرایی قابل دانلود آماده است.

## امکانات

- رابط WPF فارسی با فهرست رقابت‌ها، فهرست مسابقات و پنل احتمال‌ها.
- اتصال اختیاری به API-Football از طریق کلید شخصی کاربر.
- کشف کاتالوگ رقابت‌های گزارش‌شده از API-Football و رقابت‌های موجود در OpenLigaDB.
- دریافت برنامهٔ مسابقات در بازهٔ ۷ روز آینده، تاریخچهٔ اخیر برای مدل و فید زنده از API-Football.
- دریافت مسابقات لیگ‌های انتخاب‌شدهٔ OpenLigaDB، با پوشش وابسته به دادهٔ واقعی ارائه‌دهنده.
- ذخیرهٔ تنظیمات در `%LOCALAPPDATA%\KoaZa\Foreseer\settings.json` و داده‌ها در SQLite محلی.
- تازه‌سازی زمان‌بندی‌شده و کنترل فاصلهٔ درخواست‌ها برای کمک به رعایت سهمیهٔ رایگان.
- مدل پایهٔ پواسون برای 1X2، دوشانس، مجموع گل‌های ۱٫۵/۲٫۵/۳٫۵، گل‌زنی دو تیم، گل‌زدن هر تیم و پنج نتیجهٔ دقیق با بیشترین احتمال.
- امتناع از تولید احتمال در صورت ناکافی بودن تاریخچهٔ محلی.
- شناسهٔ داخلی و شناسهٔ ارائه‌دهنده برای تفکیک مسابقات و رقابت‌ها.

## نیازمندی‌ها

- Windows 10/11 x64
- .NET 8 SDK برای اجرای توسعه‌ای و ساخت محلی
- اتصال اینترنت برای دریافت داده از ارائه‌دهنده‌ها
- کلید API-Football برای کاتالوگ گسترده‌تر و فید زنده؛ OpenLigaDB برای برخی داده‌ها بدون کلید قابل استفاده است.

## اجرای توسعه‌ای

در PowerShell، از پوشهٔ پروژه:

```powershell
dotnet restore .\KoaZa.Foreseer.csproj
dotnet build .\KoaZa.Foreseer.csproj -c Release
dotnet run --project .\KoaZa.Foreseer.csproj -c Release
```

برای ساخت بستهٔ مستقل ویندوز x64:

```powershell
dotnet publish .\KoaZa.Foreseer.csproj -c Release -r win-x64 --self-contained true -p:PublishSingleFile=true -p:IncludeNativeLibrariesForSelfExtract=true -o .\publish\win-x64
```

یا از PowerShell، اسکریپت `build.ps1` را اجرا کنید.

## دریافت فایل اجرایی از GitHub

Workflow در `.github/workflows/windows-build.yml` با push به شاخهٔ `main` اجرا می‌شود و بستهٔ `KoaZa-Foreseer-win-x64.zip` را به‌عنوان artifact نگه می‌دارد.

1. وارد بخش [Actions مخزن](https://github.com/KoaZa-SH/KoaZa-Foreseer/actions) شوید.
2. اجرای موفق **Windows desktop build** را باز کنید.
3. از بخش **Artifacts**، فایل `KoaZa-Foreseer-win-x64` را دریافت کنید.
4. ZIP را استخراج و `KoaZa.Foreseer.exe` را اجرا کنید.

برای ساخت یک GitHub Release نسخه‌دار، یک tag با پیشوند `v` (مثلاً `v0.2.0`) بسازید؛ workflow در صورت موفقیت بسته را به Release همان tag پیوست می‌کند.

## تنظیم API-Football

1. از [وب‌سایت رسمی API-Football](https://www.api-football.com/) حساب بسازید و کلید خود را دریافت کنید.
2. برنامه را باز کنید و کلید را در قسمت اتصال وارد کنید.
3. «ذخیرهٔ تنظیمات» و سپس «تازه‌سازی داده‌ها» را انتخاب کنید.
4. رقابت‌های موردنیاز را فعال کنید و تنظیمات را ذخیره کنید.

کلید در مخزن یا فایل نمونه قرار داده نشده است. در نسخهٔ فعلی، کلید به‌صورت متن محلی در فایل تنظیمات ذخیره می‌شود؛ رایانه و فایل تنظیمات را ایمن نگه دارید. استفاده از Windows Credential Manager برای نسخهٔ بعدی توصیه می‌شود.

## سهمیه و محدودیت‌های داده

- API-Football سهمیهٔ رایگان و محدودیت‌های وابسته به پلن دارد؛ فهرست رقابت‌ها به معنای تضمین دادهٔ زنده یا آمار پیشرفته برای همهٔ آن‌ها نیست.
- برنامه داده‌ها را محلی نگه می‌دارد و فاصلهٔ درخواست‌ها را برای کمک به مدیریت سهمیه کنترل می‌کند؛ نرخ تازه‌سازی زنده به سهمیهٔ حساب و پاسخ ارائه‌دهنده بستگی دارد.
- پوشش کرنر، کارت، شوت، ترکیب، ضرایب و آمار لحظه‌ای به دادهٔ موجود برای هر رقابت و مجوز پلن وابسته است. این نسخه احتمال این بازارها را محاسبه نمی‌کند.
- مدل فعلی از میانگین گل مسابقات کامل ذخیره‌شده استفاده می‌کند؛ هنوز تعدیل پیشرفتهٔ قدرت حریف، میزبانی، مصدومیت، ترکیب، کالیبراسیون و اعتبارسنجی زمانی کامل نشده است.
- تاریخچهٔ محلی ممکن است برای بسیاری از تیم‌ها ناکافی باشد. در این حالت، برنامه احتمال نمی‌سازد و کمبود داده را گزارش می‌کند.
- تطبیق هوشمند یک رقابت بین چند ارائه‌دهنده کامل نیست؛ شناسه‌های منبع جداگانه نگه داشته می‌شوند تا از ادغام اشتباه جلوگیری شود.
- هر نسخهٔ اجرایی باید پس از build موفق در ویندوز و تست دستی رابط و اتصال منابع بررسی شود.

## ساختار پروژه

- `Models/`: مدل‌های دامنه و تنظیمات
- `Services/`: ارائه‌دهندگان داده، SQLite، تنظیمات و مدل احتمال
- `ViewModels/`: state و فرمان‌های رابط
- `MainWindow.xaml`: رابط WPF
- `.github/workflows/windows-build.yml`: ساخت و بسته‌بندی ویندوز
